# WebGUI 会话级输入隔离与生成态锁定设计

## 背景

当前 `webgui` 在会话切换时存在两个耦合问题：

1. 输入草稿使用全局单值状态，切换会话后会出现草稿串线（“消息穿梭”）。
2. 输入区与底部工具栏的禁用逻辑部分依赖组件局部发送态，切换会话后会出现“原本生成中的会话按钮被误解锁”。

这两个问题本质上都来自“会话维度状态未隔离”。

## 目标

1. 草稿按会话隔离：`A` 会话输入不影响 `B` 会话。
2. 草稿按会话持久化：Webview 重载/IDE 重启后可恢复。
3. 生成态按会话隔离：
   - 当 `A` 生成中切到 `B`（idle），`B` 可正常输入和发送。
   - 回到 `A` 时仅允许“停止生成”，其余输入与底部操作禁用。

## 范围与非目标

### 范围

- `packages/opencode/webgui/src/components/MessageInput/*`
- `packages/opencode/webgui/src/state/uiBridgeState.ts`
- 与会话 busy/idle 联动的底部按钮禁用逻辑

### 非目标

- 不修改消息协议与服务端接口
- 不改会话列表、标签拖拽、消息渲染逻辑
- 不引入新的全局状态管理库

## 方案选择

本次评估 3 个方案，最终选择方案 A。

- A（本次采用）：**会话级状态重构**
  - 草稿改为 `drafts[sessionID]`
  - 锁定逻辑以 `SessionContext` 会话 busy/idle 为唯一真相
  - 优点：一致性最好，长期维护成本最低
  - 代价：改动中等，需要补齐迁移与回归测试

- B：强制重挂载 `MessageInput` + 独立草稿 Map
  - 优点：落地较快
  - 缺点：编辑器历史与桥接同步存在更多边角风险

- C：最小热修补丁
  - 优点：开发最快
  - 缺点：无法完整满足“按会话持久草稿恢复”，后续高概率返工

## 架构与组件设计

### 1) 草稿状态（会话隔离）

- 将单一 `input` 表示升级为会话级 `drafts` 映射。
- 读写规则：
  - 输入变更时：仅更新当前 `sessionID` 的草稿
  - 会话切换时：先落盘旧会话草稿，再恢复新会话草稿

### 2) 生成态锁定（会话隔离）

- UI 锁定改为读取 `SessionContext` 的会话 busy/idle 真相。
- 当前会话 busy 时：
  - 编辑区禁用
  - `Agent/Model/Variant`、附件、精简按钮禁用
  - 仅“停止生成”保留可用

### 3) UI Bridge 持久化

- 持久化结构升级为会话草稿可恢复的版本化格式（`v2`）。
- 与 host 同步仍保留输入 debounce，但作用对象从全局单值改为会话草稿结构。

## 数据流

### 会话切换

1. 保存 `currentSessionID` 对应草稿。
2. 切换激活会话。
3. 加载 `nextSessionID` 草稿并回填编辑器。

### 输入与发送

1. 输入变更仅影响当前会话草稿。
2. 发送后 busy 由会话级状态驱动，UI 根据当前会话 busy/idle 切换。
3. `abort` 始终针对当前会话 ID；virtual session 维持不可 abort 约束。

## 错误处理与边界策略

1. **快速切换竞态**：使用会话激活 token，过期异步结果丢弃。
2. **会话删除**：清理对应 `drafts[sessionID]`，避免幽灵草稿。
3. **virtual → real 迁移**：materialize 后迁移草稿键，避免丢输入。
4. **host 持久化失败**：本地状态优先，不阻断输入；记录 warning 并重试下一次同步。
5. **状态不一致兜底**：UI 以会话 busy/idle 为准，不信任局部瞬时态。

## 测试与验收

### 自动化测试

1. 会话草稿隔离：A/B 草稿来回切换准确恢复。
2. 会话草稿持久化：重载后按会话恢复。
3. 生成态隔离：A busy 切到 B 可发送；回 A 仅 stop 可用。
4. 按钮禁用矩阵：busy 会话下除 stop 外全部禁用。
5. 旧状态兼容：`v1(input)` hydrate 到新结构不崩溃。

### 手动验收

1. 不再出现会话切换后的消息/草稿穿梭。
2. 生成中会话回切后，底部仅停止按钮可操作。
3. 多会话草稿在 IDE 重启后仍可按会话恢复。

## 风险与回退

- 风险：状态迁移与切换竞态导致偶发回填错误。
- 缓解：版本化 hydrate + token 失效保护 + 针对切换竞态的测试覆盖。
- 回退：若出现线上问题，可先退回 `uiBridgeState` 新结构与禁用矩阵变更，保留原会话切换链路。
