# WebGUI StatusPopover MCP 面板高度与工具折叠设计

## 背景

当前 `StatusPopover` 的 MCP tab 在工具数量较多时会持续向下撑高，影响可视区域与操作连贯性。用户提出两个明确需求：

1. 面板限制最大高度，超出后出现滚动条。
2. MCP 工具列表支持收起/展开。

此外，已确认交互偏好：

- 最大高度：`60vh`
- 工具列表默认状态：`默认收起`

## 目标

1. StatusPopover 在视觉上保持 `modern-card` 风格不变，同时限制最大高度。
2. 仅内容区滚动，顶部 tab 区不随内容滚动。
3. MCP 每个 server 工具列表支持展开/收起，且默认收起。
4. 不改变既有 server/tool switch、busy、refresh 行为。

## 非目标

1. 不新增“全部展开/全部收起”。
2. 不做折叠状态持久化（localStorage）。
3. 不调整工具启停写配置链路。

## 方案对比

### 方案 A：弹层整体滚动 + `<details>`

- 优点：改动最小。
- 缺点：tab 头也滚动；样式与可访问性控制较弱。

### 方案 B：内容区滚动 + 显式折叠状态（推荐）

- 优点：交互清晰，tab 固定，测试稳定，可访问性好（`aria-expanded`）。
- 缺点：需要新增少量折叠状态管理。

### 方案 C：方案 B + 持久化状态

- 优点：重度使用场景更友好。
- 缺点：超出当前需求，复杂度增加。

结论：采用方案 B。

## 详细设计

### 1) 布局与滚动

在 `StatusPopover.tsx` 中将弹层内容拆分为“头部 tab 区 + 内容区”：

1. 外层容器增加 `max-h-[60vh]` 与纵向布局（`flex flex-col`）。
2. 内容区容器增加 `min-h-0 overflow-y-auto`，用于承载各 tab 的 panel。
3. 保持既有 `w-[360px]` 与定位样式。

这样可保证：当 MCP 工具很多时，仅 panel 内容滚动，tab 区保持固定可见。

### 2) MCP 工具折叠

在 MCP server 行中新增折叠按钮：

1. 每个 server 维护本地折叠状态 `open[name]`（默认 `false`）。
2. 仅当 `item.tools.length > 0` 时显示“展开/收起”按钮。
3. 按钮使用 `aria-expanded` 表示状态，支持无障碍。
4. `item.enabled === false` 时不强制自动展开；仍按用户点击控制。

默认行为：所有 server 工具列表初始收起。

### 3) 状态切换时机

`open` 状态仅在当前弹层生命周期内生效：

1. 打开弹层时初始化为空对象（等价全部收起）。
2. 手动刷新 MCP 或切换 tab 不重置用户当前展开项。
3. 关闭后再次打开恢复默认收起。

## 测试策略

更新 `StatusPopover.test.tsx`：

1. 断言弹层含 `max-h-[60vh]`，并含内容区滚动类（`overflow-y-auto`）。
2. 断言 MCP 工具列表默认不渲染（收起）。
3. 点击“展开”后渲染工具项，再次点击“收起”隐藏。
4. 断言折叠按钮 `aria-expanded` 状态切换。

## 验收标准

1. MCP 工具过多时面板高度不超过视口 60%。
2. 超出区域出现垂直滚动条。
3. 工具列表支持按 server 展开/收起，默认收起。
4. 现有工具开关与刷新 loading 行为保持不退化。
