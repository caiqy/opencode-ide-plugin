# Design: WebGUI 快捷短语设置与输入区联动

> 在设置与聊天区打通短语配置和调用

## 明确背景

当前 WebGUI 缺少“预设输入片段”的统一管理与高效调用能力，用户需要在聊天前后反复复制粘贴。  
本设计在不改上游 Config/schema 的前提下，只在 webgui 内完成设置、展示、交互与持久化闭环。

---

## 设定目标与非目标

### 目标

1. 在设置页新增独立 Tab，并在顶部提供输入模式下拉：双击发送、确认后发送、回填输入框。
2. 在聊天输入框上方展示标签区，默认单行不换行且可横向滚动，支持展开全部与收起。
3. 建立统一数据模型：`标题 + 正文`，标签显示标题，执行使用正文。
4. 标签仅在“双击”时触发模式效果，单击不触发发送或回填。
5. “确认后发送”统一复用全局 `ConfirmModal`。
6. 可用状态与输入框一致，AI 生成中所有标签与相关按钮均禁用。
7. 存储采用新增 `quickPhraseRepo`，基于 `scopedStorage` 且 `scope=global`。
8. 提供可持续更新的预置短语机制。
9. 支持隐藏与排序。
10. 预置短语不可删除且不可编辑，仅允许隐藏与排序。
11. 自定义短语支持添加、编辑、删除、隐藏、排序。
12. 不设置数量与长度限制。

### 非目标

1. 不修改 opencode 上游 Config、schema、解析与合并逻辑。
2. 不新增服务端接口与跨端同步协议。
3. 不引入权限系统或多租户隔离策略。

---

## 对比方案

### 方案 A：单列表混合存储（推荐）

将预置与自定义写入同一仓储视图，条目带 `source` 字段（`preset | custom`）和能力约束。  
排序与隐藏以“最终展示序”为核心存储，渲染层直接消费。

**优点**

- 数据流最短，设置页和聊天区都只依赖一个读取结果。
- 排序/隐藏逻辑统一，后续新增分组或搜索改动小。

**缺点**

- 需要在仓储层严控“预置不可编辑/删除”的保护逻辑。

### 方案 B：双列表分离存储

预置与自定义分别存储，展示时在 UI 层合并。  
排序通过“合并索引映射”单独维护。

**优点**

- 预置与自定义边界清晰。
- 回退某一侧数据更直接。

**缺点**

- 合并与重排逻辑复杂，边界场景更多。
- 设置页与聊天区都要重复处理合并策略。

### 方案 C：静态预置 + 自定义动态，仅存用户增量

预置写死在代码，自定义与用户操作（隐藏/排序）只记录增量补丁。  
启动时“预置 + 补丁”计算最终态。

**优点**

- 预置更新可通过版本化常量快速发布。
- 存储体积小。

**缺点**

- 增量补丁冲突与迁移策略更复杂。
- 计算链路更长，调试成本更高。

---

## 确认决策

采用 **方案 A（单列表混合存储）**。  
它在当前需求下实现成本最低，且最容易保证设置页与聊天区的一致行为。

补充决策如下：

1. `quickPhraseRepo` 作为唯一读写入口，屏蔽组件层分支判断。
2. 预置短语以“内置清单 + 初始化合并”注入仓储，后续更新通过提升预置版本并执行幂等合并。
3. 排序使用稳定 `order` 字段，隐藏使用 `hidden` 布尔字段。
4. 交互模式保存在同一 repo 的全局设置中，聊天区实时订阅。

---

## 拆分架构

### 模块划分

- `quickPhraseRepo`
  - 基于 `scopedStorage`，`scope=global`。
  - 提供 `list/getMode/setMode/create/update/remove/reorder/toggleHidden/syncPreset`。

- 设置页 Tab
  - 新增“快捷短语”Tab。
  - 顶部模式下拉 + 下方列表管理区（预置区、自定义区可同页分组展示）。

- 聊天输入区扩展
  - 输入框上方新增标签条。
  - 默认单行横向滚动，点击“展开”显示多行全部标签，再可“收起”。

- 全局确认弹窗
  - 在“确认后发送”模式下，双击标签先打开 `ConfirmModal`。
  - 用户确认后才提交正文到发送链路。

### 数据模型

```ts
type QuickPhraseItem = {
  id: string
  title: string
  body: string
  source: "preset" | "custom"
  hidden: boolean
  order: number
  preset_version?: string
}

type QuickPhraseMode = "double_send" | "confirm_send" | "fill_input"
```

预置项能力约束由 repo 保证：`source === "preset"` 时禁止编辑正文、标题与删除。  
数量和长度不做校验上限，只保留基础空值校验与去空格处理。

## 描述流转

### 初始化流

1. 应用启动时，`quickPhraseRepo.syncPreset()` 将内置预置与本地数据做幂等合并。
2. 合并规则保留用户的 `hidden/order`，并补齐新增预置项。

### 设置流

1. 用户在 Tab 顶部切换模式后，repo 写入全局存储并广播订阅。
2. 用户对短语执行增删改、隐藏、排序时，repo 即时持久化并返回新列表。

### 聊天区触发流

1. 聊天区读取“可见且按 order 排序”的列表并渲染标签标题。
2. 单击标签不触发动作，双击标签按模式执行正文。
3. `double_send` 直接发送正文。
4. `confirm_send` 打开全局 `ConfirmModal`，确认后发送正文。
5. `fill_input` 将正文回填输入框，不自动发送。
6. 输入框不可用时，标签区及展开/收起按钮全部不可用。

---

## 处理异常

1. 存储读取失败时回退到内置预置 + 默认模式（`fill_input`），并提示轻量错误。
2. 存储写入失败时保留当前 UI 状态不提交，提示“保存失败，请重试”。
3. 预置同步异常不阻塞页面渲染，记录日志并继续使用上次可用数据。
4. 确认弹窗链路失败时中止发送，不污染输入框内容。
5. 排序提交失败时回滚到提交前顺序并提示错误。

---

## 制定测试

### 单元测试

1. `quickPhraseRepo`：CRUD、隐藏、排序、模式读写、预置幂等合并。
2. 约束测试：预置不可编辑/删除，自定义可完整操作。
3. 可用态联动：输入框禁用时标签与按钮禁用。

### 组件测试

1. 设置页 Tab 渲染模式下拉与列表操作区。
2. 聊天区默认单行滚动、展开后多行展示、收起恢复单行。
3. 标签仅双击触发，单击无副作用。
4. `confirm_send` 必经 `ConfirmModal`。

### 集成测试

1. 设置页修改后聊天区实时生效。
2. 三种模式分别验证发送/确认/回填链路。
3. AI 生成中全量不可用，生成结束后恢复可用。

---

## 定义验收标准

1. 仅改 webgui，未触及 opencode 上游 Config/schema。
2. 设置页存在“快捷短语”Tab，顶部可切换三种输入模式。
3. 短语结构为标题+正文，标签展示标题、执行正文。
4. 标签只有双击触发模式行为。
5. 确认后发送使用全局 `ConfirmModal`。
6. 输入框上方标签区默认单行横滑，支持展开与收起。
7. 标签区可用状态与输入框一致，AI 生成中全部禁用。
8. 存储通过 `quickPhraseRepo + scopedStorage(global)`。
9. 内置预置短语可后续更新，且不可删除不可编辑，仅可隐藏与排序。
10. 自定义短语支持添加、编辑、删除、隐藏、排序。
11. 不存在数量与长度上限限制。
12. 全链路测试通过且关键交互无回归。
