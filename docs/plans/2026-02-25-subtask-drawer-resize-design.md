# 子任务弹层左边缘拉伸设计

## 背景

当前子任务弹层宽度固定为 `w-[min(520px,100%)]`。在窄视口或长文本场景下，固定宽度不够灵活。目标是让用户可通过弹层左边缘拖拽，动态调整宽度。

## 目标

- 支持从左边缘拖拽调整子任务弹层宽度
- 同时支持“变宽 / 变窄”
- 默认宽度保持 `520px`
- 宽度限制为：最小 `360px`，最大 `90vw`
- 不持久化宽度（每次打开恢复默认值）

## 非目标

- 不改动子任务消息渲染逻辑
- 不引入全局状态或本地存储
- 不支持键盘调整宽度（本次仅鼠标/指针拖拽）

## 备选方案与结论

### 方案 A（采用）

在抽屉左边新增显式拖拽手柄，使用 `pointerdown / pointermove / pointerup` 驱动宽度更新，并在更新时做 `clamp(360px, next, 90vw)`。

**优点**：交互可控、语义清晰、跨浏览器表现稳定。  
**缺点**：需要新增少量状态与事件处理代码。

### 方案 B（不采用）

依赖原生 `resize: horizontal`。

**问题**：手柄位置和视觉不可控，通常不符合“左边缘拖拽”的交互要求。

### 方案 C（不采用）

无显式手柄，仅靠边缘热区触发拖拽。

**问题**：可发现性差，误触概率高。

## 详细设计

### 组件结构

在 `SubtaskDrawer.tsx` 中保持现有结构，新增一个位于抽屉左边缘的拖拽手柄元素：

- 手柄宽度建议 `6~8px`
- 手柄高度铺满抽屉
- 默认透明，`hover`/拖拽时显示弱分隔线
- 鼠标样式为 `col-resize`

### 状态模型

- `width`: 当前抽屉宽度，初始 `520`
- `drag`: 当前拖拽会话状态（是否拖拽中、起始 `clientX`、起始宽度）

状态仅在 `SubtaskDrawer` 内部维护，不外提。

### 宽度计算

拖拽中计算公式：

- `delta = startX - currentX`
- `next = startWidth + delta`
- `max = window.innerWidth * 0.9`
- `width = clamp(360, next, max)`

语义：鼠标左移变宽，右移变窄。

### 事件流

1. `pointerdown`（仅主键）进入拖拽
2. 记录起始坐标和起始宽度
3. `pointermove` 实时计算并更新宽度
4. `pointerup` / `pointercancel` 结束拖拽并清理监听

为防止拖拽过程中鼠标离开手柄导致中断，使用 pointer capture 或 document 级监听兜底。

### 样式与布局

- 抽屉从固定类宽改为受控 `style.width`
- 同时保留最大宽约束（`90vw`）
- 拖拽期间临时禁用文本选择（避免误选）
- 手柄事件需阻止冒泡，避免触发 backdrop 点击关闭

## 边界与错误处理

- 视口过窄时，按 `max=90vw` 截断
- 拖拽被取消时（`pointercancel`）强制结束拖拽状态
- 仅响应主键拖拽，忽略右键/中键

## 测试计划

扩展 `SubtaskDrawer.test.tsx`：

1. 默认宽度为 `520px`
2. 向左拖拽后宽度增大
3. 向右拖拽后宽度减小
4. 最小宽度不小于 `360px`
5. 最大宽度不超过 `90vw`
6. `pointerup` 后停止更新宽度

## 验收标准

- 可在左边缘拖拽，宽度实时变化
- 拖拽方向与视觉反馈一致
- 宽度严格落在 `[360px, 90vw]`
- 关闭后重新打开恢复默认 `520px`
- 现有“点击遮罩关闭”“Esc 关闭”行为不回归
