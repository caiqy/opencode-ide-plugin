# WebGUI 状态点弹层对齐设计

## 说明背景

当前 WebGUI 缺少一套与官方 app 对齐的状态总览入口。用户只能分散感知连接、服务与扩展状态，难以快速判断当前环境是否可用。

本次目标是为 WebGUI 新增“状态点 + 弹层”交互，并以官方 app 的状态面板为原型和功能参考。UI 承载明确采用 WebGUI，不复用官方 app 原生实现。

---

## 明确目标

1. 提供一个由状态点触发的状态弹层，点击可打开，再次点击可关闭。
2. 让 WebGUI 的信息结构、状态表达和交互预期尽量与官方 app 状态面板对齐。
3. 在弹层内固定提供四个 tab，顺序为 `servers → mcp → lsp → plugins`。
4. 弹层默认激活 tab 为 `servers`。
5. 在数据不足时仍保留 tab 本身，并展示空态或失败态，而不是直接隐藏。
6. 对暂不开放或受限的操作，保持入口可见但禁用，并明确说明原因。

---

## 排除范围

1. 不在本文内实现任何代码，也不拆解具体开发任务。
2. 不重新定义官方 app 的状态语义，仅在 WebGUI 侧做对齐映射。
3. 不在首版引入新的全局状态中心或跨页面状态管理重构。
4. 不在首版补齐 servers 维度的历史统计、性能分析或深度诊断能力。

---

## 比较方案

### 方案 A：完全照搬官方 app 结构与交互

优点是认知迁移成本最低。缺点是官方 app 与 WebGUI 的技术边界不同，直接照搬容易引入不适配的交互和实现负担。

### 方案 B：仅保留状态点，点击后跳转独立页面

优点是实现简单，信息承载空间更大。缺点是打断当前操作流，也不符合“状态点即面板入口”的预期。

### 方案 C：参考官方 app 信息架构，在 WebGUI 中实现轻量弹层（采纳）

优点是兼顾对齐目标与 WebGUI 现实边界。缺点是需要为部分能力设计“展示但禁用”与“空态保留”的降级规则。

### 采纳理由

采纳方案 C。它既满足“原型和功能参考官方 app”的已确认决策，也能明确落在 WebGUI 的组件体系内完成适配。

---

## 收敛结构

整体采用“三层结构”：状态点触发层、弹层容器层、tab 内容层。状态点只负责开关与摘要，弹层负责布局与切换，tab 只消费统一 view model。

边界上不让 tab 直接依赖彼此内部状态。公共能力只包括：当前打开状态、激活 tab、刷新动作、基础加载态与错误态协议。

### 状态点

状态点位于现有 WebGUI 顶层可见区域，用于表达“当前有可查看的系统状态”。点击一次打开弹层，再次点击关闭；点击弹层外部或按下 Esc 也应关闭。

状态点只展示聚合后的轻量信号，不承载详细列表。它不是第五个 tab，也不直接暴露复杂操作。

### 弹层容器

弹层负责：定位、开关、焦点管理、tab 切换和统一状态骨架。它不拥有业务数据，只消费各 tab 统一组装后的 view model。

弹层内 tab 顺序固定为 `servers → mcp → lsp → plugins`，默认激活 `servers`。首版不提供用户自定义排序，也不根据数据存在与否动态重排。

### tab 内容

每个 tab 各自维护独立的数据分区与渲染逻辑。tab 之间共享视觉框架，但不共享领域判断。

如果某个 tab 没有数据源、数据为空或请求失败，仍保留 tab，并分别显示空态或失败态。这样可保持结构稳定，也符合官方 app 的面板认知。

---

## 明确适配

新增一层局部“状态弹层适配层”，建议落在 header 附近的 hook 或 provider 内。它统一负责聚合 `connectionState`、`ideBridge` 与 SDK 数据，再输出给状态点、弹层和各 tab。

各 tab 只读取适配层产出的 view model，不直接散落访问底层数据源。这样可以把状态语义、降级规则和刷新策略收敛到一处，避免同一状态在不同区域被各自解释。

### 归属

状态弹层适配层归属于 WebGUI header 局部范围，不扩展成新的全局状态中心。它服务于状态点与状态弹层。

`OfflineBanner` 继续使用现有 App 层 `connectionState`。状态点、弹层与 `OfflineBanner` 共享同一组连接术语，但聚合失败与陈旧提示只属于弹层内部附加语义，不改变 banner 现有触发条件。

### 聚合

适配层至少统一聚合三类输入：连接状态、IDE bridge 状态、SDK 可读数据。它负责把原始输入压平成 UI 可消费的最小模型，而不是把底层对象原样透传到 tab。

优先复用 `ProjectContext`、`IdeBridgeContext` 等现有状态来源。只有这些来源未覆盖的数据，才补局部读取，避免重复真相源。

### 禁止

禁止 `servers`、`mcp`、`lsp`、`plugins` 各自直接发起独立底层读取来拼状态真相。允许 tab 在自身需要时触发刷新动作，但刷新入口仍经由适配层统一调度。

适配层必须按数据源独立结算，可用 `allSettled`、分区快照或分区错误模型实现。不能因为某一路聚合失败，就把整个弹层一起判成失败。

## 划清职责

### servers

`servers` 首版语义收敛为三部分：OpenCode 服务连接状态、IDE bridge 状态、当前 project/path 摘要。它不是多 server 管理面板，也不承诺展示多实例、历史连接或切换能力。

它回答的问题是：现在是否连通、bridge 是否可用、当前连接落在哪个项目路径。更深的 server 细项、诊断和管理动作留待后续版本扩展。

### mcp

`mcp` 用于展示 MCP 相关服务或客户端的已知状态，包括可见实例、连接结果、失败原因和可执行操作。若某些官方 app 中存在但 WebGUI 当前无权执行的动作，也应展示为禁用态并写明限制。

### lsp

`lsp` 首版只展示“已连接 LSP 列表”。它不承诺初始化失败、不可用、能力缺失或诊断异常等更细状态。

若后端当前只提供连接中的已知条目，则前端按该列表直出。没有更细状态时，不做前端猜测补全。

### plugins

`plugins` 首版只展示已配置插件列表，数据仅基于当前实例合并配置中的 `config.plugin[]`，来源为 `sdk.config.get()` / `/config`。它不承诺运行态、加载成功、异常态或健康检查结果。

若当前实例合并配置为空，则显示空态说明，而不是推导为“无可用插件”或“插件运行异常”。

---

## 收紧边界

首版各 tab 只写当前后端已经提供或能稳定聚合出的状态。文案与展示都不应越界到“可能存在但仓库当前未稳定支持”的能力。

### servers

允许写明连接是否建立、bridge 是否连接、当前项目或路径摘要。不要写多 server 数量、实例管理、进程级重启、资源占用或历史趋势。

### lsp

允许写明已连接的 LSP 名称或条目。不要写初始化失败、不可用、功能降级、索引进度或诊断健康度。

### plugins

允许写明当前实例合并配置中声明了哪些插件。不要写插件是否真正启动、是否报错、是否被某次请求调用过。

### mcp

继续沿用现有已知数据和能力描述。若官方 app 有动作但 WebGUI 当前无权执行，只做禁用展示与原因说明。

---

## 定义来源

数据来源按“宿主状态 > 桥接层聚合 > WebGUI 状态适配层 > 视图映射”收敛。WebGUI 不直接创造业务真相，只负责消费宿主或桥接层已确认的状态信号。

建议将每个 tab 或聚合分区的输入统一映射为四类结果：`ready`、`empty`、`failed`、`stale`。弹层外单独保留 SSE 传输连接语义：`connecting`、`connected`、`disconnected`、`error`。

总状态派生规则以 SSE `connectionState` 为主真相，它只表示传输连接是否建立。`ideBridge` 只作为 `servers` tab 的次级状态与动作 gating 来源，`servers` 首版只承载 SSE 连接状态、IDE bridge 状态与当前 project/path 摘要。`plugins` 使用 `sdk.config.get()` / `/config` 返回的当前实例合并配置，不读取 `sdk.global.config.get()` / `/global/config`。

### 来源分层

1. 宿主侧或桥接层提供原始状态与能力描述。
2. WebGUI 状态适配层聚合原始输入，并把它们转换为 tab 可消费的 view model。
3. UI 层只渲染 view model，不自行推导隐式业务结论。

### 状态矩阵

先统一四类 SSE 连接语义，再在弹层内部叠加 tab 或聚合分区自己的加载结果语义。

1. `connecting`：SSE 正在建立连接。状态点与 `OfflineBanner` 继续表达传输连接进行中，弹层内容区可显示基础加载骨架。
2. `connected`：SSE 已连接。状态点显示传输连接正常，弹层再按各 tab 自身的 `ready`、`empty`、`failed`、`stale` 决定内容表达；此时 `ideBridge` 只影响 `servers` 局部表达。
3. `disconnected`：SSE 未连接。状态点仍可见，弹层以 `servers` 为主入口解释不可用原因，`OfflineBanner` 按现有规则显示离线提示。
4. `error`：SSE 传输连接本身出错。它只表示连接层异常，不复用为弹层内部聚合失败语义。

弹层内部附加语义如下：

1. `ready`：分区成功取得可展示数据。
2. `empty`：分区成功返回，但当前无可展示内容。
3. `failed`：分区读取失败，且当前没有可复用快照。
4. `stale`：分区最新刷新失败，但仍保留历史成功快照，并附上陈旧提示。

### 刷新

状态点打开弹层时可触发一次轻量刷新。tab 切换不应默认重复发起高成本请求，除非对应分区明确声明需要按需加载。

若刷新失败且已有历史成功数据，应保留上次成功快照，并展示“数据可能过期”“上次更新于 ...”之类的陈旧提示。若从未成功获取，则显示失败态而不是空白区。

---

## 约束动作

交互原则是“先看状态，再做有限动作”。首版重点是把状态看清，而不是把所有修复动作都搬进弹层。

### 能力矩阵

1. **可执行：** 打开弹层、关闭弹层、切换 tab、触发刷新、查看当前状态与摘要。
2. **展示但禁用：** 官方 app 已有但 WebGUI 当前无权执行的动作，例如受宿主限制的连接管理或服务动作。禁用时必须在邻近位置说明原因。
3. **首版不做：** 多 server 管理、插件运行态诊断、LSP 细粒度初始化状态、深度健康分析、跨 tab 批量操作。

### 边界

弹层中的动作以“查看”和“轻量刷新”为主。若某动作需要宿主权限、原生能力或当前后端尚未提供接口，则不假装可用。

---

## 约束交互

1. 点击状态点打开弹层，再次点击状态点关闭弹层。
2. tab 可直接切换，但顺序固定，不支持拖拽或隐藏。
3. 受限操作展示为禁用按钮或菜单项，并在邻近位置说明原因，例如“仅官方 app 支持”或“当前宿主未开放”。
4. 数据不足时保留 tab，内容区展示空态说明，例如“暂无可展示数据”。
5. 请求失败时保留 tab，内容区展示失败态说明与可重试入口。

### 处理触发

状态点触发器使用 button 语义。Enter 与 Space 均可打开或关闭弹层，并正确暴露 `aria-haspopup`、`aria-expanded` 与弹层关联关系。

弹层关闭后，按 Esc 或再次点击状态点触发器时，焦点回到状态点按钮。若用户通过点击外部控件关闭，焦点保持在用户点击的目标上，不强制拉回触发器。

### 处理浮层

header 右侧多个浮层遵循互斥打开规则。互斥范围至少包含 `StatusPopover`、`SessionDropdown`、`ActionButtons` 的更多菜单。

若用户连续点击不同入口，以最后一次显式点击为准。互斥规则由 header 层统一仲裁，不在各浮层内部各自维护；必要时应把更多菜单改成可受控开关或暴露关闭接口。

---

## 处理异常

1. **桥接未连接：** 状态点仍可见，但弹层优先展示整体不可用说明，`servers` tab 作为主解释入口。
2. **单 tab 拉取失败：** 仅该 tab 进入失败态，不阻塞其它 tab 渲染。实现上按分区独立结算，不允许一次聚合失败拖垮整个弹层。
3. **能力受限：** 展示操作入口但禁用，并给出限制文案，不做静默隐藏。
4. **部分字段缺失：** 降级为“信息不足”空态，不用前端猜测补全。
5. **弹层开关冲突：** 以最近一次显式用户点击为准，保证状态点点击始终可以打开或关闭。

### 处理重试

重试入口由适配层统一调度。首版至少支持整体刷新重试，不要求每个 tab 自行维护独立请求编排。

若某 tab 失败但存在历史成功快照，重试前继续展示旧快照并附陈旧提示。重试成功后更新时间戳并移除陈旧提示，重试失败则保留旧快照与失败说明。

---

## 制定测试

测试分为三层：状态映射测试、tab 渲染测试、交互回归测试。重点覆盖固定结构、降级规则、禁用态说明与按关闭来源区分的焦点处理。

### 映射测试

1. `connectionState`、`ideBridge` 与 SDK 数据可被统一聚合为稳定的 view model，并明确拆分传输连接语义与弹层内部结果语义。
2. 总状态派生以 SSE `connectionState` 为主真相，`ideBridge` 只影响 `servers` 次级状态与动作 gating；`servers` 首版只包含 SSE 连接状态、IDE bridge 状态与 project/path 摘要。
3. 缺失字段不会导致 tab 消失，只会进入空态或失败态。
4. 四个 tab 输出顺序固定，始终为 `servers → mcp → lsp → plugins`，默认激活 `servers`。
5. `servers` 只包含连接状态、bridge 状态、project/path 摘要，不混入多 server 管理字段。
6. `plugins` 只基于 `sdk.config.get()` / `/config` 返回的当前实例合并配置中的 `config.plugin[]` 生成列表，不读取 `sdk.global.config.get()` / `/global/config`，也不推导运行态或异常态。
7. `lsp` 只基于已连接列表渲染，不推导初始化失败或不可用等更细状态。
8. `OfflineBanner` 继续只跟随 App 层现有 `connectionState` 触发，不被 header 局部适配层改写；tab 的 `failed` 或 `stale` 不会被回写成连接层 `error`。

### 渲染测试

1. 状态点点击后打开弹层，再次点击关闭。
2. 四个 tab 始终可见，不因数据缺失被隐藏。
3. 默认进入 `servers`，切换后再次打开时遵循既定默认或产品约定，不出现随机激活 tab。
4. `servers` 首版只渲染连接状态、bridge 状态、project/path 摘要，不出现超范围信息。
5. `plugins` 读取当前实例合并配置中的 `config.plugin[]`；为空配置时显示空态，不显示运行错误文案。
6. `lsp` 无数据时显示空态，不显示“初始化失败”等未被后端支持的状态。
7. 受限操作会显示为禁用态，并包含原因文案。
8. 刷新失败且存在历史成功数据时，页面继续展示旧快照，并显示 `stale` 提示与上次更新时间。

### 交互测试

1. button 触发器可被键盘聚焦，Enter 与 Space 都能开关弹层。
2. `aria-expanded` 会随开关同步变化；按 Esc 或再次点击状态点关闭时，焦点回到触发器；点击外部控件关闭时，焦点留在用户点击目标。
3. tab 切换只切内容，不改变固定顺序。
4. header 右侧多个浮层互斥打开，范围包含 `StatusPopover`、`SessionDropdown`、`ActionButtons` 更多菜单。
5. 单 tab `failed` 不会影响其它 tab 查看，且分区错误不会升级成连接层 `error` 或整个弹层失败。
6. 失败态支持重试时，重试行为经由适配层统一调度。
7. Esc、外部点击与状态点再次点击都可关闭弹层；其中 Esc 与再次点击状态点会回焦到触发器，外部点击关闭时不强制改写焦点目标。

## 定义验收

1. WebGUI 中存在可见状态点，点击可打开状态弹层，再次点击可关闭。
2. 弹层以官方 app 状态面板为原型和功能参考，但 UI 明确采用 WebGUI 实现。
3. 四个 tab 顺序固定为 `servers → mcp → lsp → plugins`，任何场景下都不重排。
4. 弹层默认激活 `servers`，且 header 右侧浮层遵循互斥打开，范围包含 `StatusPopover`、`SessionDropdown` 与更多菜单。
5. `servers` 首版仅表达 OpenCode 服务连接状态、IDE bridge 状态与当前 project/path 摘要。
6. `plugins` 首版仅表达 `sdk.config.get()` / `/config` 返回的当前实例合并配置中的 `config.plugin[]` 已配置插件列表，不使用 `sdk.global.config.get()` / `/global/config`，也不承诺运行态或异常态。
7. `lsp` 首版仅表达已连接 LSP 列表，不承诺更细状态。
8. 受限操作必须“展示但禁用并说明”，而不是直接隐藏。
9. 任一 tab 在数据不足时仍保留，并按分区显示 `empty` 或 `failed`。
10. 刷新失败且已有历史成功数据时，必须保留旧快照并显示 `stale` 提示。
11. 单个 tab 的异常不会导致整个弹层不可用。
12. `OfflineBanner` 继续沿用 App 层现有触发条件，状态弹层适配层只与其共享连接术语；弹层内部的 `failed` 与 `stale` 属于附加语义，不直接驱动 banner。
13. 文档中的边界、职责、数据流和测试策略可直接作为后续实现依据。
