判定口径：

- `已直接覆盖`：现有测试直接断言该需求的结果或边界。
- `仅间接覆盖`：现有测试只覆盖相邻机制，没有直接断言该需求本身。
- `未覆盖`：指定测试集中没有现成断言。

补测口径：

- 只把 `未覆盖` 和 `高风险仅间接覆盖` 标为需要补测。
- 低风险 `仅间接覆盖` 不列入补测。

## 当前结论

- `updating/latest/failed` 的最终 UI 断言不存在“未覆盖 / 仅间接覆盖”缺口：`SessionContext.test.tsx` 直接锁定状态链映射，`FooterPanels.test.tsx` 直接锁定当前 session 状态透传，`FileChangesPanel.test.tsx` 直接锁定三类正式文案。

- 后端 scheduler 的主干语义、前端 activation/foreground 释放、真实路由 foreground gate、`prompt/processor -> markDirty` 主输出链、以及 Diff 状态链展示，现在都已有直接回归锁定。
