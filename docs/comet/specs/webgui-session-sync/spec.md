# WebGUI 跨目录会话同步与会话目录作用域

## 需求与交互目标

WebGUI 必须保证：只要会话由当前后端进程服务，无论其创建目录是否与 WebGUI 实例目录相同，界面都能实时反映其执行状态与消息，并在完成后正确结束“生成中”；新建与复用会话只在当前实例目录内发生；VS Code 插件自动化测试不污染用户真实数据；Composer 不会因为不完整数据或恢复异常而永久锁定。

## 事件流：全项目事件流与目录分发

1. WebGUI 不再订阅目录级 `/event`，改为订阅全项目事件流 `/global/event`（v1 SDK `sdk.global.event()`），保留断线重连、`server.connected` 处理与 heartbeat 忽略等既有行为。
2. `/global/event` 的每条数据信封为 `{ directory, project, payload }`；客户端必须先解包 `payload` 再交给现有事件分发链路，不得把信封整体当作事件对象。只替换 URL 而不解包会导致所有事件的 `type` 为空，属于禁止实现。
3. 事件处理不得按“当前实例目录”丢弃其他目录的事件：`message.updated`、`message.part.updated`、`message.part.delta`、`message.removed`、`message.part.removed`、`session.status`、`session.idle`、`session.error`、`permission.*`、`question.*` 等事件按其 `sessionID` 归属进入现有 store 与通知逻辑。
4. 客户端可以忽略与当前项目无关的事件，但不得因为事件目录不同而忽略同项目会话的事件。
5. 事件处理失败（例如未知事件类型）不得中断连接或阻塞后续事件。

## 新建/复用会话的目录作用域

1. “+（新建会话）”的复用只允许发生在当前 WebGUI 实例目录内：
   - 草稿指针复用检查：读取到的草稿会话若目录与当前实例目录不一致，视为不可复用；
   - 空会话兜底扫描：只扫描目录与当前实例目录一致的默认标题空会话（消息数为零、无父会话、未归档）。
2. 目录比较必须归一化（Windows 盘符大小写与路径分隔符），避免同一目录被误判为不同目录。
3. 当没有可复用的当前目录空会话时，在当前目录创建新会话；不得因为其他目录存在空会话而切换或复用。
4. 保留既有复用语义：同一目录内仍复用最近的空默认会话，不改为每次强制新建。

## 测试数据隔离

1. VS Code 插件自动化测试启动的后端进程必须继承指向临时数据目录的环境（`XDG_DATA_HOME` 以及必要的 `XDG_CACHE_HOME`、`XDG_CONFIG_HOME`、`XDG_STATE_HOME`），使会话、消息、数据库与快照写入临时目录。
2. 测试运行结束后，用户真实数据目录（`%USERPROFILE%\.local\share\opencode` 等）不得新增测试产生的会话记录。
3. 隔离机制只影响测试宿主启动的后端，不改变生产环境下扩展启动后端的方式与数据位置。

## Composer 会话设置恢复兜底

1. 会话设置恢复（selection 恢复）必须容忍不完整的用户消息：缺少 `model` 或 `agent` 的消息（例如发送后未被服务端消息替换的乐观消息）不得导致异常；此时跳过该消息并回退到更早的完整用户消息，或视为无法恢复。
2. 会话激活流程的任意异常（包括消息加载失败、恢复逻辑抛错、请求被中断）都必须保证 `selectionSessionId` 收敛到当前会话或显式 null 对应的可交互状态，使 Composer 不显示“正在切换会话设置…”。
3. 兜底不得吞掉错误：异常仍需记录到 console；只保证状态收敛与可交互。
4. 在恢复失败时仍使用当前已有配置，保持既有“继续使用当前配置”的提示语义。

## 验收场景

- Scenario: 跨目录会话实时更新
  - GIVEN 同一后端进程内存在一个创建目录与 WebGUI 实例目录不同的会话
  - WHEN 该会话在后台执行且用户在 WebGUI 中打开它
  - THEN WebGUI 无需刷新即可显示流式消息与工具进展
  - AND 执行完成后界面不再显示“生成中”

- Scenario: 切走再切回跨目录会话
  - GIVEN 一个跨目录会话正在后台执行并产生消息
  - WHEN 用户切到其他会话后再切回该会话
  - THEN 界面显示后台已产生的消息内容
  - AND 已结束的执行不再显示“生成中”，Composer 可以继续输入

- Scenario: 点击加号只复用当前目录的空会话
  - GIVEN 当前目录与其他目录各存在一个空默认会话
  - WHEN 用户点击“+（新建会话）”
  - THEN 只会复用当前目录的空会话
  - AND 不会选中或切换到其他目录的空会话

- Scenario: 草稿指针指向其他目录会话
  - GIVEN 恢复出的草稿指针指向一个目录与当前实例不同的会话
  - WHEN 用户点击“+（新建会话）”
  - THEN 该会话不被复用
  - AND WebGUI 在当前目录创建或复用会话

- Scenario: 测试数据隔离
  - GIVEN 在用户机器上运行 VS Code 插件自动化测试
  - WHEN 测试启动后端并创建会话
  - THEN 测试数据写入隔离的临时目录
  - AND 用户真实数据目录不新增测试遗留会话

- Scenario: 不完整用户消息不阻塞会话激活
  - GIVEN 消息缓存中只存在缺少 `model`/`agent` 的乐观用户消息
  - WHEN 用户切换或恢复该会话
  - THEN 恢复过程不抛异常导致流程中断
  - AND Composer 不显示“正在切换会话设置…”，可以继续输入

- Scenario: 恢复异常后 Composer 自动恢复
  - GIVEN 会话设置恢复过程抛出任意异常
  - WHEN 激活流程结束
  - THEN Composer 自动解除禁用并恢复可输入状态
  - AND 异常被记录且不导致永久锁定

- Scenario: 既有行为不回归
  - GIVEN 本次改动完成
  - WHEN 运行 WebGUI 与 VS Code 插件的自动化测试
  - THEN 新增与既有测试均通过
  - AND 会话列表跨目录可见、消息提交、停止生成与上下文统计等既有行为保持不变
