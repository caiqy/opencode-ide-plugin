# WebGUI 优雅打断与二次确认强制打断

## 需求与交互目标

在 WebGUI 对话界面中实现两阶段打断机制：第一次点击停止按钮触发优雅打断，等待当前大模型输出与伴随的工具调用完整执行落库后，不再启动后续大模型推理，安全平滑收尾；按钮变为醒目警示红并提供微动效果，输入框上方展示等待收尾的提示横幅；在等待期间，若用户再次点击红色按钮，弹出确认弹窗，经用户确认后执行强制打断，立即中断服务端执行；未决的问题与权限审批在优雅打断触发时自动拒绝，消除流程阻塞。

## 详细行为规范

1. **停止按钮两阶段状态**：
   - 普通执行中：灰色圆底 + 白色方块，Tooltip 显示“停止生成”。
   - 优雅打断等待中：按钮背景切换为警示红（`bg-red-500 hover:bg-red-600 text-white`）并带有微动效果，Tooltip 变为“已请求停止，再次点击强制打断”。
   - 再次点击红色按钮：唤起全局 `ConfirmModal` 模态弹窗，提示：“确定要强制打断吗？强制打断将立即终止当前工具执行和生成，可能导致未保存的操作中断。”，提供“强制打断”与“取消”操作。
   - 确认强制打断：调用底层强制打断接口，立即终止 Fiber 并恢复会话为空闲。
   - 取消强制打断：关闭弹窗，继续维持优雅打断等待状态。

2. **提示横幅**：
   - 触发优雅打断后，在 `MessageInput` 输入框上方展示提示横幅：`⏸️ 正在等待当前操作完成以优雅停止... 若需立即终止，请点击右下角红色按钮`。
   - 当等待时长超过 30 秒时，横幅文本自动切换并强化警示：`当前工具执行耗时较长，若需立即停止，请点击右下角红色按钮强制打断`。
   - 会话恢复为空闲后，横幅自动消失。

3. **输入与编辑行为**：
   - 在优雅打断等待期间，输入框不锁定，允许用户提前输入下一条 Prompt 草稿。
   - 会话恢复为空闲后，输入框自动获得焦点。

4. **审批与提问拦截**：
   - 触发优雅打断时，自动拒绝当前会话内所有未处理的 Question 与待确认的 Permission，避免会话卡在等待审批。

5. **服务端退出机制**：
   - `POST /session/:sessionID/abort` 接受可选请求体 `{ graceful?: boolean }`。
   - 若 `graceful: true`，在会话运行时标记该会话请求优雅停止；在 `SessionPrompt.run` 循环边界（大模型流式输出完毕且当前步骤关联的工具全部执行完成后），检测该标记并 break 退出循环，Assistant 消息正常完成落库（不标记为 `interrupted`）。
   - 若 `graceful` 为 `false` 或缺省，保持既有行为立即取消 Fiber。

## 验收场景

- Scenario: 第一次点击停止按钮触发优雅打断
  - GIVEN WebGUI 中 AI 正在生成内容或执行工具
  - WHEN 用户第一次点击停止按钮
  - THEN 按钮背景变为警示红并带有微动效果
  - AND Tooltip 显示为“已请求停止，再次点击强制打断”
  - AND 输入框上方显示等待收尾的提示横幅

- Scenario: 优雅打断后安全完成当前回合退出
  - GIVEN 会话处于优雅打断等待状态
  - WHEN 当前文字流式输出完成且伴随的工具调用执行落库
  - THEN 服务端不再启动下一轮大模型推理
  - AND 会话平滑退出回到 Idle 状态

- Scenario: 优雅打断期间输入框可编辑且转 Idle 后自动聚焦
  - GIVEN 会话处于优雅打断等待状态
  - WHEN 用户在输入框中输入文字草稿
  - THEN 输入框保持正常可编辑
  - AND 当会话转为 Idle 后，红色按钮恢复为发送图标，输入框自动获得焦点，Assistant 消息保留正常耗时且不显示 interrupted

- Scenario: 再次点击红钮弹出强停确认弹窗且取消保持等待
  - GIVEN 会话处于优雅打断等待状态且按钮呈红色
  - WHEN 用户再次点击红色停止按钮
  - THEN 界面弹出 ConfirmModal 确认弹窗
  - AND 用户点击取消后，弹窗关闭且会话继续保持优雅打断等待状态

- Scenario: 确认弹窗中确认强制打断
  - GIVEN 用户已打开强制打断确认弹窗
  - WHEN 用户点击“强制打断”按钮
  - THEN 系统调用立即强停接口中断服务端 Fiber 并停止会话

- Scenario: 优雅打断自动拒绝待办提问与权限审批
  - GIVEN 当前会话存在未回答的 Question 或待审批的 Permission
  - WHEN 用户触发优雅打断
  - THEN 系统自动 Reject 掉这些待办项，消除流程阻塞

- Scenario: 优雅打断等待超过 30 秒更新高亮提示
  - GIVEN 会话处于优雅打断等待状态
  - WHEN 等待时长超过 30 秒
  - THEN 横幅文案自动更新为引导强制打断的警示文案

- Scenario: 服务端 abort 接口支持优雅打断与强杀兼容
  - GIVEN 客户端向 `POST /session/:sessionID/abort` 发送请求
  - WHEN 请求体传入 `{ graceful: true }` 时，服务端在当前回合结束后安全退出循环
  - AND 当请求体未传入或 `graceful: false` 时，服务端执行立即强杀
