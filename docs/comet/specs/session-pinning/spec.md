# 会话钉住

## 目标

历史会话下拉列表允许用户显式钉住会话，并在列表展示、搜索结果与增量加载后始终将钉住会话排在未钉住会话之前。

## 行为要求

### 钉住优先级

- 历史列表必须把所有已加载的钉住根会话组成连续的首部区域。
- 钉住会话内部必须按 `time.updated` 降序排列。
- 未钉住会话必须继续按 `time.updated` 降序排列。
- 当前会话只有被用户显式钉住时才属于钉住区域。
- 钉住或取消钉住本身不得改变 `time.updated`。

### 持久化与兼容性

- 钉住状态必须随 Session 持久保存，并在使用同一数据目录的客户端之间共享。
- IDE、WebGUI 或服务重启后，钉住状态必须保留。
- 钉住状态必须使用 Session 已有的开放 metadata 扩展能力表达，不得新增旧版官方 `opencode app` 必须识别的响应字段。
- 不识别钉住 metadata 的客户端必须仍能读取和使用该 Session，不得因未知键报错。
- 官方 app 可以忽略钉住 metadata，并继续使用现有客户端更新时间排序与分页行为；本次变更不得要求其增加钉住操作入口或理解新的必填字段。

### 搜索与分页

- 标题搜索必须保留匹配结果的钉住优先级。
- 增量加载不得把钉住会话放到未钉住会话之后。
- 数据获取必须能够返回应位于首部的旧钉住会话，不能仅在按更新时间截取首屏后进行本地重排。

### 用户操作与同步

- 已钉住会话必须在标题旁常驻显示小图钉。
- 钉住/取消钉住按钮必须位于现有悬浮操作区，并在当前会话操作区常驻可用。
- 切换按钮必须用当前状态对应的中文 tooltip 说明“钉住会话”或“取消钉住”。
- 操作成功后，列表必须通过现有会话同步链路反映新状态和顺序。
- 操作成功后必须仅通过图钉和排序变化提供反馈，不显示成功 toast。
- 操作失败时，不得把未被服务端接受的状态保留为成功状态，并必须显示中文错误 toast。

### 新会话与 Fork

- 新建会话默认不得钉住。
- 从已钉住会话 fork 时，新会话不得继承钉住状态。
- fork 必须继续复制原会话的其他 metadata，只移除本功能使用的钉住键。

## 验收场景

### 旧会话优先

给定已钉住会话 A 比未钉住会话 B 更早更新，当历史列表打开时，则 A 显示在 B 前面。

### 钉住组沿用活跃度顺序

给定两个已钉住会话 A 和 B，且 A 的最后更新时间晚于 B，当历史列表打开时，则 A 显示在 B 前面；执行钉住或取消钉住不会改写任一会话的最后活动时间。

### 搜索保留优先级

给定搜索结果同时包含钉住和未钉住会话，当用户输入标题查询时，则所有匹配的钉住会话先于匹配的未钉住会话。

### 加载更多保持分区

给定首屏之后仍有历史会话，当用户加载更多时，则钉住区域仍连续位于列表最前面，未钉住区域继续按最后更新时间降序。

### 旧客户端兼容

给定会话 metadata 包含钉住键，当不识别该键的官方 app 或旧客户端读取会话时，则会话读取正常完成，未知键被安全忽略，官方 app 可继续采用其现有更新时间排序。

### 状态与操作可识别

给定一个已钉住会话，当该行未悬浮时，则标题旁仍显示图钉；当该行进入悬浮或当前会话操作状态时，则用户可使用带中文 tooltip 的按钮取消钉住。

### Fork 不继承钉住

给定原会话已钉住且包含其他 metadata，当用户 fork 该会话时，则新会话未钉住、其他 metadata 仍被保留。

### 操作反馈

给定用户钉住或取消钉住会话，当操作成功时，则图钉与列表顺序更新且不显示成功 toast；当操作失败时，则原状态与顺序保持不变并显示中文错误 toast。
