```markdown
# 上游同步检查单 (Upstream Sync Checklist)

## 概述

Brief description: this checklist guides a developer through safely merging upstream opencode changes into the ide-plugin branch using an isolated sync branch.

## 前置条件 (Prerequisites)

- Clean working tree (`git status` shows clean)
- On `ide-plugin` branch
- Remotes: `opencode` → `anomalyco/opencode.git`, `origin` → `caiqy/opencode-ide-plugin.git`
- `git rerere` enabled (`git config --get rerere.enabled` returns `true`)

## 第 1 步：准备 (Preparation)

- [ ] Verify clean working tree: `git status`
- [ ] Checkout ide-plugin: `git checkout ide-plugin`
- [ ] Fetch upstream: `git fetch opencode`
- [ ] Record upstream HEAD: `UPSTREAM_SHA=$(git rev-parse --short opencode/dev)`

## 第 2 步：冲突预览 (Dry-Run Conflict Preview)

- [ ] Run dry-run: `git merge-tree --write-tree --name-only ide-plugin opencode/dev`
- [ ] Review output: exit code 0 = no conflicts, exit code 1 = conflicts listed
- [ ] Count conflicting files and assess risk using the conflict zone reference table
- [ ] Decision point: proceed with merge or wait

**回滚路径 (Rollback):** 此步骤不修改任何内容，无需回滚。

## 第 3 步：创建 Sync 分支 (Create Sync Branch)

- [ ] Create branch: `git checkout -b sync/YYYYMMDD` (replace YYYYMMDD with today's date)
- [ ] Verify: `git branch --show-current` shows `sync/YYYYMMDD`

**回滚路径:** `git checkout ide-plugin && git branch -D sync/YYYYMMDD`

## 第 4 步：执行合并 (Perform Merge)

- [ ] Merge upstream: `git merge opencode/dev --no-edit`
- [ ] If no conflicts: proceed to Step 6
- [ ] If conflicts: proceed to Step 5

**回滚路径:** `git merge --abort` — 立即恢复到合并前状态。如果已经 commit，`git checkout ide-plugin && git branch -D sync/YYYYMMDD` 重来。

## 第 5 步：冲突解决 (Conflict Resolution)

**处理顺序：**

### 5a. bun.lock (机械解决，每次必冲突)

- [ ] `git checkout --theirs bun.lock`
- [ ] `bun install`
- [ ] `git add bun.lock`

### 5b. 低风险文件

- `packages/app/src/pages/session/use-session-commands.tsx` — Take upstream (SolidJS TUI code)
- `packages/opencode/test/session/llm.test.ts` — Align test fixtures

### 5c. 中风险文件

- `packages/opencode/package.json` — Manual merge: verify version changes, check patch deps
- `packages/opencode/src/session/compaction.ts` — Manual merge: preserve both sides' logic
- `packages/opencode/src/session/message-v2.ts` — Manual merge: message format
- `packages/opencode/src/skill/index.ts` — Manual merge: preserve skill permission overlay

### 5d. 高风险文件 (⚠️ 需要特别注意)

- `packages/opencode/src/config/config.ts` — **保留下游 config overlay (tools, patch)**
- `packages/opencode/src/mcp/index.ts` — **保留下游 setEnabled/setToolEnabled**
- `packages/opencode/src/provider/provider.ts` — **保留下游 normalizeAnthropic SSE 补丁**
- `packages/opencode/src/server/instance/index.ts` — **新冲突区域，仔细比对**
- `packages/opencode/src/server/server.ts` — **⚠️ 关键：确保 WebGUI /app 挂载点保留**

### 5e. 完成冲突解决

- [ ] `git add <all-resolved-files>`
- [ ] `git merge --continue`

**回滚路径:** `git merge --abort` 可在任何时候取消合并。

## 第 6 步：补丁验证 (Patch Verification)

- [ ] Check bun install output for patch warnings
- [ ] Verify 4 patches still apply:
  - `@ai-sdk/anthropic@3.0.64`
  - `@ai-sdk/provider-utils@4.0.21`
  - `@standard-community/standard-openapi@0.2.9`
  - `solid-js@1.9.10`
- [ ] If any patch fails: check if upstream upgraded the dependency version, update patch if needed

## 第 7 步：快速验证 (Quick Verification)

- [ ] Type check: `cd packages/opencode && bun typecheck`
- [ ] Verify WebGUI mount: check `packages/opencode/src/server/server.ts` still imports from `webgui/server/app.ts`
- [ ] (Full build verification is Phase 2's job — minimal checks here)

## 第 8 步：集成到主分支 (Integrate to Main Branch)

- [ ] `git checkout ide-plugin`
- [ ] `git merge sync/YYYYMMDD --no-ff -m "sync: absorb upstream opencode/dev (N commits)"`
  - Replace N with actual commit count: `git rev-list --count $(git merge-base ide-plugin opencode/dev)..opencode/dev`

## 第 9 步：标记同步点 (Tag Sync Point)

- [ ] `git tag sync/upstream-$(git rev-parse --short opencode/dev)`

## 第 10 步：清理 (Cleanup)

- [ ] Delete sync branch: `git branch -d sync/YYYYMMDD`
- [ ] Verify no stale sync branches: `git branch | grep sync/`

## 冲突区域参考 (Conflict Zone Reference)

| File                                           | Risk             | Strategy                                    |
| ---------------------------------------------- | ---------------- | ------------------------------------------- |
| bun.lock                                       | LOW (mechanical) | Accept upstream → bun install regenerate    |
| packages/app/...use-session-commands.tsx       | LOW              | Take upstream (SolidJS TUI)                 |
| packages/opencode/package.json                 | MEDIUM           | Manual merge, check patch deps              |
| packages/opencode/src/config/config.ts         | **HIGH**         | Manual — preserve config overlay            |
| packages/opencode/src/mcp/index.ts             | **HIGH**         | Manual — preserve setEnabled/setToolEnabled |
| packages/opencode/src/provider/provider.ts     | **HIGH**         | Manual — preserve normalizeAnthropic SSE    |
| packages/opencode/src/server/instance/index.ts | **HIGH**         | Manual — new zone, compare carefully        |
| packages/opencode/src/server/server.ts         | **HIGH**         | Manual — CRITICAL: preserve /app mount      |
| packages/opencode/src/session/compaction.ts    | MEDIUM           | Manual merge                                |
| packages/opencode/src/session/message-v2.ts    | MEDIUM           | Manual merge                                |
| packages/opencode/src/skill/index.ts           | MEDIUM           | Manual merge                                |
| packages/opencode/test/session/llm.test.ts     | LOW              | Align test fixtures                         |

## 常见陷阱 (Common Pitfalls)

1. **bun.lock 手动解决** — 永远不要手动解决 bun.lock 冲突，始终通过 bun install 重新生成
2. **忘记验证补丁** — 合并后必须检查 4 个 patch 是否仍然有效
3. **server.ts 挂载点丢失** — 上游重构可能移除 WebGUI /app 挂载点，每次合并后必须检查
4. **合并前未安装依赖** — 验证前必须先 bun install
5. **遗留 sync 分支** — 合并成功后必须删除 sync 分支
6. **Effect.js 迁移类型错误** — 上游正在迁移到 Effect.js，合并后立即 typecheck

## 建议合并频率 (Recommended Merge Cadence)

每周一次为佳。间隔越长，冲突越复杂。
```
