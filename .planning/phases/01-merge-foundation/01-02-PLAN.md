**Step-by-step execution:**

**Preparation (步骤 1):**

```bash
git status  # Verify clean working tree
git checkout ide-plugin
git fetch opencode
UPSTREAM_SHA=$(git rev-parse --short opencode/dev)
echo "Upstream HEAD: $UPSTREAM_SHA"
```

**Dry-Run (步骤 2):**

```bash
git merge-tree --write-tree --name-only ide-plugin opencode/dev
echo "Exit code: $?"
```

Record the conflicting file list. Compare against the 12 files from RESEARCH.md — note any differences (upstream may have changed since research was done).

**Create Sync Branch (步骤 3):**

```bash
# Use today's date
git checkout -b sync/$(date +%Y%m%d)
git branch --show-current
```

**Perform Merge (步骤 4):**

```bash
git merge opencode/dev --no-edit
```

If conflicts, proceed through conflict resolution. If merge succeeds cleanly (unlikely given 12 known conflicts), skip to verification.

**Conflict Resolution (步骤 5):**

Follow the checklist order (low → medium → high risk):

5a. **bun.lock** (mechanical):

```bash
git checkout --theirs bun.lock
bun install
git add bun.lock
```

5b. **Low-risk files** — resolve per checklist guidance. For `packages/app/...use-session-commands.tsx`, take upstream:

```bash
git checkout --theirs "packages/app/src/pages/session/use-session-commands.tsx"
git add "packages/app/src/pages/session/use-session-commands.tsx"
```

5c. **Medium-risk files** — manually merge, preserving both sides' logic:

- `packages/opencode/package.json` — accept upstream version changes, ensure patch dependencies remain listed
- `packages/opencode/src/session/compaction.ts` — preserve both upstream changes and downstream logic
- `packages/opencode/src/session/message-v2.ts` — merge message format changes
- `packages/opencode/src/skill/index.ts` — preserve downstream skill permission overlay

5d. **High-risk files** — these require careful manual merge:

- `packages/opencode/src/config/config.ts` — **MUST preserve downstream config overlay (tools, patch sections)**
- `packages/opencode/src/mcp/index.ts` — **MUST preserve downstream setEnabled/setToolEnabled additions**
- `packages/opencode/src/provider/provider.ts` — **MUST preserve downstream normalizeAnthropic SSE patch**
- `packages/opencode/src/server/instance/index.ts` — new conflict zone, carefully compare upstream vs downstream changes
- `packages/opencode/src/server/server.ts` — **⚠️ CRITICAL: MUST verify WebGUI /app mount point is preserved after merge.** Check that the file still imports from `webgui/server/app.ts` and registers the `/app` route.

**Resolution principle (per D-01 and AGENTS.md):** 尽量同时保留上游和 webgui 的逻辑. When both-sides preservation is not possible for a specific conflict hunk, leave a `TODO: DECISION NEEDED` comment and resolve the rest — the user will decide in the checkpoint task.

5e. Stage and complete:

```bash
git add <all-resolved-files>
git merge --continue
```

**Patch Verification (步骤 6):**

```bash
# Check bun install output (already run in step 5a)
# Verify patches exist — look for patch-related warnings in bun install output
ls patches/
```

If any patch fails to apply, document which patch and the error message.

**Quick Verification (步骤 7):**

```bash
cd packages/opencode && bun typecheck
```

Record result. If typecheck fails, document errors but DO NOT try to fix them — that's Phase 2's scope. The important thing is that the merge completed and the checklist was followed.

Also verify WebGUI mount:

```bash
grep -n "webgui" packages/opencode/src/server/server.ts
grep -n "/app" packages/opencode/src/server/server.ts
```

**DO NOT** proceed to integration (步骤 8-10) yet — that happens after the user verifies in the checkpoint task below.

**Checklist corrections:** If any checklist step was inaccurate, unclear, or missing information based on this real execution experience, update `docs/upstream-sync-checklist.md` with corrections. Document what was changed and why.

**Important constraints:**

- Per project AGENTS.md: 合并时尽量同时保留上游和 webgui 的逻辑，需要二选一时提出方案让用户选择
- Do NOT force-push or modify ide-plugin branch directly
- Do NOT delete the sync branch yet — the user needs to verify first
- If the merge is too complex to complete (>50% of high-risk files have irreconcilable conflicts), abort with `git merge --abort` and document what happened in the SUMMARY

**Integration (步骤 8):**

```bash
# Get the commit count for the merge message
UPSTREAM_COMMIT_COUNT=$(git rev-list --count $(git merge-base ide-plugin opencode/dev)..opencode/dev)

git checkout ide-plugin
git merge sync/$(date +%Y%m%d) --no-ff -m "sync: absorb upstream opencode/dev ($UPSTREAM_COMMIT_COUNT commits)"
```

Note: If the sync branch name doesn't match today's date (because it was created on a different day), use `git branch | grep sync/` to find the actual branch name.

**Tag Sync Point (步骤 9):**

```bash

```

**Cleanup (步骤 10):**

```bash
# Delete sync branch
SYNC_BRANCH=$(git branch | grep 'sync/' | tr -d ' ')
git branch -d "$SYNC_BRANCH"

# Verify no stale sync branches remain
git branch | grep sync/ || echo "No stale sync branches — clean"
```

**If user reported issues in checkpoint:** Address the specific issues first, then re-verify before integration. Do NOT integrate if issues remain unresolved.

```bash
git checkout ide-plugin

echo "Merge aborted. ide-plugin is unchanged."
```
